# Risk register

Ranked by impact × likelihood. Items marked **[verify]** are assumptions about Android or Magisk
internals that have not yet been confirmed against source code or a device. Each lists how and when
it will be checked.

| # | Risk | Mitigation | Phase |
|---|---|---|---|
| 1 | **AIDL effects HAL.** Some devices running Android 14+ use the AIDL effects HAL, which does not load legacy `AUDIO_EFFECT_LIBRARY_INFO_SYM` libraries. On those devices, the approach in this repository does nothing. | `customize.sh` and the app detect `android.hardware.audio.effect.IFactory` in `service list`; v1 aborts installation with a clear message. An AIDL adapter would be a separate phase, after verifying the AOSP entry points and config file name in `hardware/interfaces/audio/aidl/default/EffectFactory.cpp`. **[verify]** Test device (Galaxy S9, LineageOS 19.1): HIDL `android.hardware.audio.effect@5.0`, so not affected. | 4 |
| 2 | **32-bit audio HAL on 64-bit devices.** Many arm64 devices still run a 32-bit audio HAL. | Always build both ABIs and install both `lib/soundfx` and `lib64/soundfx`. The device script reports the HAL's ELF class. **Confirmed** on the test device: `/vendor/bin/hw/android.hardware.audio@2.0-service` is 32-bit and loads `/vendor/lib/soundfx`, so `armeabi-v7a` is the ABI that runs there. Both ABIs pass the full test suite on it. | 3–4 |
| 3 | **Effects config variants.** Vendors use `/odm/etc`, `/vendor/etc`, `/vendor/etc/audio/<sku>/` and legacy `.conf` files, and rename the file. The HAL and audioserver may read different files. | `customize.sh` patches every `audio_effects*.xml` in those directories with the idempotent `sp-xmlpatch` (which skips files that are not effects configurations). **Confirmed** on the test device: the HAL's `libeffectsconfig` (Samsung) reads `audio_effects_sec.xml`, audioserver's (LineageOS) reads `audio_effects.xml`; both are patched. Devices with only legacy `.conf` files are refused (v1). | 4 |
| 4 | **Partitions Magisk cannot overlay**, such as a separate `/odm`. | Their copies go to `bind/` and `post-fs-data.sh` bind-mounts them (HAL services start after post-fs-data). Covered by the host script tests; **not exercised on a device** (the test device's `/odm` has no effects XML). | 4 |
| 5 | **SELinux.** Overlaid files need the right contexts, and the HAL domain name varies by vendor. | Copies get `vendor_configs_file` / `system_file`, libraries `vendor_file` (the AOSP labels of those directories). The data directory gets `soundpower_data_file` from `sepolicy.rule`, readable by the `hal_audio_server` attribute (so the vendor's domain name does not matter). **Verified** with Magisk 31.1 on the test device's policy (offline, `--apply` + `--save`): attribute rules are accepted and the type gets `file_type` and `data_file_type`. If the type is not in the loaded policy, `post-fs-data.sh` loads the rules live. It asks the kernel (`/sys/fs/selinux/context`) because the label cannot tell: Magisk may set a context the policy does not define, and the kernel then treats the file as `unlabeled`. **Both paths verified** on the test device: preloaded rules (`magisk --install-module`), and the live fallback after installing through `update-binary` (the Magisk app's path, where Magisk printed "Unable to find preinit dir"); the HAL reads `state.bin` in both, with no denials. | 4 |
| 6 | **Paths that bypass software effects:** compress offload, direct/hi-res/bit-perfect USB output, AAudio MMAP exclusive mode. | Document them. The diagnostics screen shows how many instances are live. **[verify]** whether the framework turns off offload when a non-offloadable postprocess effect is enabled. | 4, 8 |
| 7 | **Untrusted callers.** Any app holding `MODIFY_AUDIO_SETTINGS` can create the effect and send commands into a privileged HAL process. | Strict size validation, clamping, no casts of input buffers, all-or-nothing decoding, a libFuzzer target (ASan + UBSan) over command sequences. Its first run found one bug (a C `bool` read from caller bytes, undefined for values other than 0/1), now fixed with a regression test. Accepted residual risk: other apps can change EQ settings (same as AOSP's equalizer). | 3 |
| 8 | **Concurrency.** `command()` and `process()` run on different HAL threads. | Lock-free audio path (triple buffer, atomics, a hazard pointer for engine swaps). ThreadSanitizer stress tests (GCC and Clang) with audio, control, configuration and instance-churn threads: clean. | 2–3 |
| 9 | **A HAL crash means no sound for the whole device.** | `service.sh` watchdog: 3 restarts of the effects HAL process within 3 minutes of boot, or a new tombstone with a frame in `libsoundpower.so`, disable the module for the next boot (logged in `log/boot.log`). "New" means not in the list `post-fs-data.sh` saves, not newer than the boot: the test device's clock reads 2018 until late in the boot. Manual recovery and Magisk safe mode are in [debugging](debugging.md). | 4 |
| 10 | **Vendor linker namespace and STL.** Vendor processes can only load LL-NDK dependencies, and `libc++_shared.so` is not available. | Build with `c++_static`; link only `liblog`, `libc`, `libm`, `libdl`. A build-time test (also in CI) checks the `NEEDED` list and exports with `llvm-readelf`, and 16 KB segment alignment on 64-bit ABIs. **Verified** on the test device: the 32-bit `android.hardware.audio@2.0-service` loads it from `/vendor/lib/soundfx`. | 3–4 |
| 11 | **Hidden API access** (`AudioEffect(UUID,UUID,int,int)` and `set/getParameter(byte[],byte[])` are not public SDK) may break on a future Android version. | HiddenApiBypass (exempts `AudioEffect` from the checks; the members are then used through reflection). **Works** on the test device (Android 12, HiddenApiBypass 6.2). Part of the fallback is already there: the app writes `state.bin` as root after every change, and the library reloads it when an instance is created. A live reload (inotify) is added only if needed. | 5 |
| 12 | **Other audio mods** (ViPER4Android, JamesDSP, Dolby ports) overlaying the same XML. | `customize.sh` warns about every enabled module that replaces one of the same files (only one copy is mounted). Merging with another module's copy is not attempted. | 4 |
| 13 | **Control instance on a track-less session.** The design assumes AudioFlinger accepts an effect on a private session with no tracks. | **Confirmed** on the test device: AudioFlinger puts such an effect on the first output thread (the HAL logs `created instance for session 225, io 13`), and a music stream's instance follows the app's changes live (its `STATUS` flags in `dumpsys` follow the app's bypass switch). Fallback, not needed so far: attach the control instance to the session of a silent `AudioTrack` of the app. | 5 |
| 14 | **Volume semantics.** Whether stream volume is applied before or after session effects decides how loudness compensation reads the listening level. **[verify]** | Measure on a device before implementing loudness compensation. | 6 |
| 15 | **Latency.** The limiter lookahead (1.5 ms default) is not reported to the framework. | Small compared with output buffering. Documented. | — |
| 16 | **CPU scales with sessions.** Postprocess creates one instance per playing session. | Benchmark on the test device (Snapdragon 845, stereo 48 kHz, 256-frame blocks, % of real time per instance): EQ32 + limiter = 1.07 % arm64 / 1.74 % armv7 on a big core, 4.3 % / 5.6 % on a little core. During a curve change (crossfade) it roughly doubles, briefly. 10 bands cost 0.46 % / 0.76 % (big) and 1.8 % / 2.6 % (little). The target (< 2 % of a big core on arm64) is met; armv7 matters most on the test device. Float/SIMD biquads are an option if real devices need more headroom. | 2–3 |
| 17 | **AudioPolicy effect budget.** AudioPolicy adds the declared `cpuLoad` and `memoryUsage` of every live effect and refuses new effects above about 43 MIPS / 512 KB. On the test device, LineageOS AudioFX alone already declares 166 KB. | The descriptor declares `cpuLoad = 0`, `memoryUsage = 1`, so instances on many sessions never exhaust the budget. The real cost is measured (risk 16) and reported in `STATUS`. | 3 |

| 18 | **The root manager refuses without asking.** On the test device, Magisk 31.1 rejects root for every new app without showing its prompt (`su: request rejected`, also for a plain `su` run with the app's uid), while existing grants keep working. The cause on that device is not known yet. | The app controls an already loaded effect without root: setup shows root as denied, and the equalizer warns that changes are not saved for the next boot. The user grants root in Magisk. Installing the module from the app and persisting `state.bin` from the app are not yet verified on a device for this reason. | 5 |
